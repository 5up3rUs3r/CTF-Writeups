# Phantom Nonce — Crypto (450 pts, 11 solves)

**Author:** DR programmer
**Flag:** `r00t{ECDSA_n0nces_fr0m_an_LCG_c0llaps3_t0_a_quadratic_in_d__rhin0_charge}`

## Description

PerfectRoot's release-signing service uses ECDSA over secp256k1. Several signatures were captured, generated by a signer whose nonce generator has a hidden flaw.

## The Vulnerability

The per-signature nonces `k_i` were generated by an **LCG** (`k_{i+1} = A·k_i + B mod n`), not a CSPRNG. This is a classic ECDSA nonce-bias vulnerability class.

Each ECDSA signature gives:
```
k_i = z_i · s_i⁻¹ + r_i · s_i⁻¹ · d   (mod n)
```
— i.e., each `k_i` is an **affine function of the unknown private key `d`**, with known coefficients derived from the signature `(r_i, s_i)` and message hash `z_i`.

Combined with the LCG relation `k_{i+1} = A·k_i + B` across **three consecutive signature pairs**, we get enough equations to algebraically eliminate both unknown LCG parameters `A` and `B`, collapsing everything down to a **single quadratic equation in `d`**.

## Solve Steps

1. Verified all 4 given signatures against the public key directly (`R = z·s⁻¹·G + r·s⁻¹·Q`, check `R.x mod n == r`) to confirm hash convention and rule out data errors — no assumptions taken on faith.
2. Expressed each `k_i` as `k_i = α_i + β_i·d mod n` from the signature equation.
3. Substituted into the LCG relation for 3 consecutive `(k_i, k_{i+1})` pairs, eliminating `A` and `B` between equations to reach a quadratic `c₂d² + c₁d + c₀ ≡ 0 (mod n)`.
4. Solved via modular square root (Tonelli-Shanks) — two candidate roots, verified against the public key to pick the correct one.
5. Recovered `A` and `B` from the now-known nonces, confirmed by predicting a held-out `k` value and checking it against a 4th signature (`predicted k4 == actual k4: True`, `predicted k3 == actual k3: True`).

## Unsealing the Flag

The sealed flag data (73 bytes) used a keystream built from a **SHA-256 hash chain**, seeded from a pipe-delimited string of the recovered secrets:

```python
seed_str = f"kifaru|{d}|{A}|{B}"
block0 = sha256(seed_str.encode()).digest()
block1 = sha256(block0).digest()
block2 = sha256(block0 + block1).digest()   # note: folds in BOTH prior blocks, not just the last

keystream = (block0 + block1 + block2)[:73]
flag = bytes(a ^ b for a, b in zip(sealed_bytes, keystream))
```

The tricky part was `block2`: naive iterative chaining (`sha256(block1)`) matched for the first 64 bytes but broke on the final partial block — the actual construction hashes the **concatenation of both previous blocks**, not just the immediately preceding one.
