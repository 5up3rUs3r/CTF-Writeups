# Vault Keeper — Rev (Hard, 300 pts, 7 solves)

**Flag:** `r00t{VaultBr34ch_2077}`

## Description

A .NET binary (`VaultKeeper.exe`) with an accompanying decompiled C# source (`VaultKeeper.decompiled.cs`) provided directly — a "legacy access console" prompting for an access code.

## Analysis

Having the full decompiled source made this a pure re-implementation task rather than blind reverse engineering. Key structure from the source:

- Expected format: `r00t{` + exactly **16 characters** + `}`.
- The 16-char inner key is split into **4 groups of 4 bytes**.
- Each group is transformed by `Stg()` — a small per-group mixing function using 8 bytes of per-group constants (rotate/XOR/multiply-add: `Mx3(a,b) = (a*3 + b*7 + 165) mod 256`) — then **SHA-256 hashed**, and the digest must match a fixed 32-byte target slice from a table `Th0`.
- The 32-byte constant table `Rw0` (used to build those per-group constants) is itself XORed against a keystream generated by a simple 32-bit LCG (`num = num*1103515245 + 12345`), seeded from a hardcoded constant.
- An anti-debug `Probe()` check (timing-based busy loop, plus `Debugger.IsAttached`) flips one bit of the constant table if a debugger is detected — irrelevant to static analysis/reimplementation, since we never ran it under a debugger.

## Why Brute Force Works Here

SHA-256 is one-way, so we can't invert it directly — but **each group only has 4 input bytes**. Assuming a reasonable charset (alphanumeric + underscore, matching this event's flag style), 4-byte brute force is trivial (63⁴ ≈ 15.8M per group, sub-second), and **all 4 groups are independent** (no shared state between them).

## Solve Script

```python
import hashlib, string, itertools

def Xf14():
    num = 1511506142
    out = []
    for _ in range(16):
        num = (num * 1103515245 + 12345) & 0xFFFFFFFF
        out.append((num >> 16) & 0xFF)
    return out

def InitTbl():
    ks = Xf14()
    return [Rw0[i] ^ ks[i % len(ks)] for i in range(len(Rw0))]

def R8l(b, n): n &= 7; return ((b << n) | (b >> (8-n))) & 0xFF
def R8r(b, n): n &= 7; return ((b >> n) | (b << (8-n))) & 0xFF
def Mx3(a, b): return (a*3 + b*7 + 165) & 0xFF

def Stg(input4, consts8):
    out = [0,0,0,0]
    b = input4[0] ^ consts8[0]; b = R8l(b,3); b = Mx3(b, input4[1]); b ^= consts8[1]; out[0] = b
    b = input4[1] ^ consts8[2]; b = R8r(b,2); b = Mx3(b, input4[2]); b ^= consts8[3]; out[1] = b
    b = (input4[2] + consts8[4]) & 0xFF; b = R8l(b,5); b = Mx3(b, input4[3]); b ^= consts8[5]; out[2] = b
    b = (input4[3] + consts8[6]) & 0xFF; b ^= consts8[7]; b = Mx3(b, input4[0]); out[3] = b
    return bytes(out)

array = InitTbl()
charset = (string.ascii_lowercase + string.ascii_uppercase + string.digits + "_").encode()

result = [None]*4
for g in range(4):
    consts8 = array[g*8:(g+1)*8]
    target = bytes(Th0[g*32:(g+1)*32])
    for combo in itertools.product(charset, repeat=4):
        buf = Stg(list(combo), consts8)
        if hashlib.sha256(buf).digest() == target:
            result[g] = bytes(combo)
            break

flag = "r00t{" + b"".join(result).decode() + "}"
print(flag)
```

Found all 4 groups on the first pass: `Vaul`, `tBr3`, `4ch_`, `2077` → `r00t{VaultBr34ch_2077}`.

## Lesson

When you have full decompiled source, don't reverse-engineer semantics by inference — reimplement directly in your solving language and let brute force do the work where the search space is small enough (here, independent 4-byte groups against a SHA-256 hash target).
